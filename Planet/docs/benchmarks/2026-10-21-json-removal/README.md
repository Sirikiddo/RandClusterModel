# Удаление JSON из передачи данных DAG — 21 октября 2026

В Terrain, Scene и Path адаптеры передают неизменяемые структуры через `shared_ptr`, а ProcessDAG — короткие токены. Ключи полей и алгоритмы генерации, расстановки и A* сохранены. Scene/Path используют ограниченные хранилища и кэши по восемь записей. Это временный контракт одного синхронного процесса; лимита памяти в байтах пока нет.

## Измеренный результат

Медианы 15 образцов на сценарий: пять одинаковых seed в трёх независимых процессах каждой версии. Время в миллисекундах. `До` — исходные JSON-реализации **всех трёх** backend из `c435355`; `после` — текущие адаптеры. Эффект Terrain включает изменение предыдущего этапа работы.

| L6, 40 962 клетки | До, мс | После, мс | Ускорение |
|---|---:|---:|---:|
| Terrain: генерация и получение снимка | 757,246 | 128,003 | 5,92× |
| Scene: первый расчёт выделения, деревьев и моделей | 807,756 | 209,458 | 3,86× |
| Scene: изменение выделения | 404,488 | 59,706 | 6,77× |
| Scene: изменение рельефа | 829,992 | 206,587 | 4,02× |
| Path: передача снимка и первый поиск | 354,198 | 59,612 | 5,94× |
| Path: изменение цели без передачи снимка | 188,758 | 58,371 | 3,23× |
| Scene: точный повтор готового запроса | 192,130 | 0,182 | 1058,57× |

Последняя строка — **повтор с готовыми результатами**, не новая генерация. Раньше даже этот сценарий создавал JSON всего снимка, большие строковые ключи и разбирал выходные массивы. Теперь остаются сравнение структур и копирование публичного результата. Повтор Path со снимком занял 352,807 → 58,929 мс: нынешний Path DAG всё ещё исполняет узел и восстанавливает модель/граф; это не полноценный кэш навигации.

| Уровень | Terrain до → после, мс | Scene, первый запрос, мс | Path со снимком, мс |
|---|---:|---:|---:|
| L2 | 3,208 → 0,669 | 3,207 → 0,881 | 1,408 → 0,240 |
| L4 | 46,618 → 8,734 | 47,008 → 13,324 | 20,061 → 3,801 |
| L6 | 757,246 → 128,003 | 807,756 → 209,458 | 354,198 → 59,612 |

Это CPU-замеры отдельных подсистем. Они **не измеряют готовность первого кадра**, terrain mesh живой сцены, atlas, GPU upload, FPS или L10. Их нельзя складывать и выдавать за полное время интерфейса. Генераторы и построение сетки не оптимизировались.

## Методика и границы таймера

- Intel Core i7-12700H, 14 физических ядер / 20 логических процессоров, 15,63 GiB RAM; Release x64, MSVC 14.44.35207, Qt 6.8.0. См. [machine.json](machine.json).
- Уровни L2/L4/L6, generator 3, seeds 12345–12349, seaLevel 3, scale 3. `QT_HASH_SEED=0` фиксирует порядок Qt-контейнеров для сравнения контрольных сумм.
- Порядок отдельных процессов: before → after, after → before, before → after. Сборка и другой benchmark одновременно не запускались. Отдельного непротоколируемого прогрева нет; каждый процесс сначала выполняет проверки корректности.
- Terrain: создание backend до таймера; внутри `regenerateTerrain()`, проекция в простой bridge (копия снимка), получение результата по значению. Полноценного scene controller и renderer нет.
- Scene: подготовка `SceneDagRequest` и создание backend до таймера; внутри `rebuild()` с передачей входов, исполнением нужных узлов, получением выходов. Все три результата запрашиваются. `cold` означает первый запрос нового Scene backend, не очистку системных кэшей.
- Path `cold_with_snapshot` и `repeat_with_snapshot`: внутри таймера `setTerrainSnapshot()` + `findPath(0, 1)`. `goal_change`: только `findPath(0, 2)`. Эти клетки могут не иметь проходимого маршрута; таймер включает подготовку графа, но не представляет стоимость произвольного дальнего пути. Отдельные проверки гарантированно проходимых маршрутов сравниваются с прямым A*.
- Контрольные суммы считаются **после** остановки таймера. Они охватывают все поля каждой клетки, все поля каждого дерева/модели, все вершины outline, found/length и каждый ID пути. Нулевые float нормализуются, чтобы знак нуля не создавал ложного расхождения.
- Исходный JSON-вариант собран из сохранённых копий с той же конфигурацией и тем же измерителем, без отката рабочих файлов. Локальная подмена только трёх `.cpp` задана в `build/transport-all-json/reference.targets`. Сборка после изменения использует обычный `Planet.vcxproj`.

Машина показала заметный разброс: например, L6 Scene cold до — 782,670–2153,655 мс, после — 202,210–577,060 мс. Частоты, температура и внешняя нагрузка не контролировались; причина разброса не установлена. Публикуется медиана, не p95 и не гарантия задержки. Ранний предварительный прогон был медленнее; он не смешан с итоговыми чередующимися сериями.

## Проверка корректности

Все **495 пар полных контрольных сумм совпали**: 165 строк на процесс × три пары. Проверены первый запрос, повтор, изменение/возврат selection, изменение/возврат terrain, пустые запросы моделей и выделения, передача снимка для Path, изменение цели.

Измеритель дополнительно проверяет:

- путь и длину против прямого `PathBuilder` при разных `smoothMaxDelta`, совпадении start/goal, изменении проходимости и возврате рельефа;
- результаты долгоживущего Scene против нового backend после изменения visual params, offset/selection/mesh/cell модели, selection, высоты, влажности и seed;
- отсутствие выполнения Scene-узлов при неизменном повторе;
- возврат к исходному запросу после 20 разных состояний, превышающих размер кэша;
- перемещение Scene/Path backend, сохранность общего объекта после вытеснения и отклонение устаревшего токена.

Итоговая сборка прошла существующий `--benchmark`: 78 строк, ноль несовместимых результатов. Визуальная проверка OpenGL в эту работу не входила. В компиляции остаются предупреждения о кодировке ранее импортированных комментариев.
