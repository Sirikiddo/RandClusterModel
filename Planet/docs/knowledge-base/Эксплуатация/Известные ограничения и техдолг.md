# Известные ограничения и техдолг

## Критичные расхождения «код есть» / «функция работает»

1. **Отдельная регенерация руды не реализована.** `regenerateOreDeposits()` пока меняет только HUD; залежи обновляются при полной regeneration terrain.
2. **Ore animation speed — legacy API.** Текущие shader-жилы статичны, поэтому `setOreAnimationSpeed()` не влияет на изображение.
3. **DAG model placements игнорируются.** Node выполняется и benchmark считает output, runtime ECS transforms использует прямой helper.
4. **Planet particle wind физически отключён.** Для world particles `windWeight=0`, physics update не вызывается.
5. **Path line не анимируется.** Анимируется машина вдоль линии, сама линия появляется целиком.

## Архитектурное дублирование

- Активный ECS и отдельный неиспользуемый `scene::SceneGraph`.
- Active culling в scene/renderer и отдельный `TerrainCulling`.
- Legacy и DAG tree placement с близкой, но не идентичной RNG-логикой.
- Snapshot reconstruction повторяется в terrain/path/scene DAG.
- При полной DAG regeneration одна topology может строиться около шести раз: terrain, ore, scene projection и три Scene DAG node.
- `core/EngineFacade.h` рядом с реальным `dag/EngineFacade.h` повышает риск неверного include.

## Производительность

- Terrain/entity picking — линейный CPU scan всех triangles/colliders без BVH.
- Selection pipeline оптимизирован: outline использует только рёбра выбранных клеток и отдельный DAG output. Полный terrain snapshot и topology reconstruction при клике устранены.
- Path DAG каждый query десериализует полный snapshot, реконструирует topology и graph.
- Tree/model Scene DAG ключи и caches всё ещё используют полные JSON strings; caches не имеют eviction. Selection cache заменён одним `lastSelectionKey`.
- Полный `uploadScene` заново загружает все buffers и очищает path.
- Tree draw loop ограничен 96, значит placements свыше лимита существуют и могут считаться occupied, но визуально не рисуются.
- Culling меняет terrain IBO синхронно через `glBufferData`; при camera update visible indices вычисляются дважды из-за debug statistics в `hasCameraMoved`.
- OpenGL 3.3 back-face/depth culling уже включён, поэтому CPU triangle filtering частично дублирует GPU pipeline; требуется сравнение full-mesh и chunked режимов.
- Water proxy строится по всем cells, получает дополнительный `×16` subdivision и не использует terrain visibility; на L6 это около 3,93 млн triangles.
- Terrain tessellator не разделяет vertices между triangles, увеличивая CPU generation, память, upload и vertex workload.
- Surface atlas P0 исправлен и подтверждён GUI runtime L2–L5: точный spherical BVH, exact-position cache и QtConcurrent сократили atlas L4 со 165,56 до 0,504 с, полную генерацию — со 168,81 до 3,71 с. L5 завершается за 15,01 с и выполняет 5,61 млн exact tests вместо потенциальных 2,689 млрд. Отдельный формальный visual smoke checklist воды ещё не зафиксирован.
- Независимые per-cell/per-edge стадии generation выполняются последовательно и не используют доступные CPU cores.

Полный диагноз, расчёты L2–L6 и детальный план из одиннадцати направлений: [[Аудит производительности высоких subdivision]].

## Корректность состояния

- При смене subdivision ECS сохраняет числовые `currentCell`; та же цифра соответствует другой географической позиции.
- `isCellOccupied` не учитывает trees; здания и trees могут пересекаться.
- Placement Delete защищает Explorer, клавиша Delete — нет.
- `DagTerrainBackend::currentSnapshot` не отражает ручные edits height/biome; path snapshot отражает их отдельно.
- Water расположен строго на radius 1.0, а terrain Sea height может отличаться — возможны пересечения/разрывы.
- Climate generator использует global `std::srand/std::rand`.

## Render/time consistency

- Некоторые эффекты используют real elapsed time, другие фиксированные 0.016/frame, ECS — measured dt.
- Tree foliage time — static local float, общий для всех renderer instances.
- `HexSphereRenderer` включает overlays перед trees, поэтому trees могут перекрыть линии в зависимости от depth.
- Qt/OpenGL resource cleanup местами требует current context; loaders имеют защитные ветки, но lifecycle остаётся чувствительным.

## Документация и кодировка

В нескольких исходниках комментарии отображаются mojibake из-за смешанной кодировки. Это не влияет на compiled code, но усложняет поддержку. Существующие docs описывают refactor brief и не всегда отражают окончательный порядок passes.

## Общий порядок улучшений

1. Унифицировать time sources эффектов и зафиксировать контракты water/ore toggles тестами.
2. Решить судьбу DAG model placements: применять или удалить node/output.
3. Зафиксировать один scene/ECS и один culling path.
4. Добавить spatial acceleration для picking и cache topology/graph для path.
5. Усилить compatibility tests по всем cell fields, outlines, trees и paths.

Порядок именно performance-работ зафиксирован отдельно в [[Аудит производительности высоких subdivision#План исправления]].
